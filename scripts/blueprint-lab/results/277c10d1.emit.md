## Blueprint: Fix `findLandedAtDivergence` — landed satisfies, stranded still violates

### Context

`findLandedAtDivergence` in `src/services/invariant-check.ts:152-177` currently treats the two divergence directions **symmetrically**:
- `hasDoneLand=true, landedAt=null` → flagged (still correct — dual-write missed a stamp)
- `hasDoneLand=false, landedAt!=null` → flagged (WRONG post-cutover)

Per the module's own comment on `checkInvariants` (todo-kind / mission 48e1a624 in memory), **land leaves are no longer minted after the landedAt cutover** — so "no done `[LAND]` child" is the *expected* shape for a newly-landed epic, not a defect. Flagging it unconditionally makes every landed epic without a legacy land leaf a false positive.

The fix (previously drafted and abandoned on a dropped branch `277c10d1`, git history at `git show 277c10d1 -- src/services/invariant-check.ts`) makes the second direction conditional on the epic's **git branch actually being ahead of master** (via `buildEpicBranchStatus`/`makeGitProbe` in `src/services/epic-branch-status.ts:99,180`, which already compute exactly this `ahead` fact). `landedAt` set + branch **not** ahead (`ahead<=0` or unprobeable) = satisfied — no violation. `landedAt` set + branch **still ahead>0** = genuinely stranded — violation, with a message naming the ahead count.

### Files to touch

**1. `src/services/invariant-check.ts`**
- Add import: `import { buildEpicBranchStatus, makeGitProbe } from './epic-branch-status.ts';`
- Add exported type above `findLandedAtDivergence`:
  ```ts
  /** epicId -> ahead count from the git probe; null/absent = unprobeable (treated as satisfied). */
  export type AheadLookup = (epicId: string) => number | null | undefined;
  ```
- Change `findLandedAtDivergence(todos: Todo[])` signature to `findLandedAtDivergence(todos: Todo[], aheadOf?: AheadLookup)`.
- Replace the single `if (hasDoneLand !== (t.landedAt != null))` branch with two separate checks:
  - `hasDoneLand && t.landedAt == null` → push violation, reason `'epic has a done [LAND] leaf child but landedAt is null'` (unchanged).
  - `!hasDoneLand && t.landedAt != null` → compute `const ahead = aheadOf?.(t.id) ?? 0;` and only push a violation when `ahead > 0`, with reason `` `epic has landedAt set but branch is still ahead>0 of master (ahead=${ahead}) — stranded` ``.
- Update the doc comment above the function to note the asymmetry (land leaves no longer minted post-cutover, so landedAt alone satisfies; only genuine git-stranding via `AheadLookup` still violates).
- Update `checkInvariants(project)` (`invariant-check.ts:180-183`) to build the ahead lookup and pass it through:
  ```ts
  export function checkInvariants(project: string): InvariantViolation[] {
    const todos = listTodos(project, { includeCompleted: true });
    const branchReport = buildEpicBranchStatus(todos, makeGitProbe(project));
    const aheadById = new Map(branchReport.epics.map((e) => [e.epicId, e.ahead]));
    const aheadOf: AheadLookup = (epicId) => aheadById.get(epicId);
    return [...findViolations(todos), ...findLandedAtDivergence(todos, aheadOf)];
  }
  ```
  This is transparent to both call sites (`src/services/system-status.ts:288`, `src/mcp/setup.ts:2223`) since they only call `checkInvariants(project)` — no signature change there.

**2. `src/services/__tests__/invariant-check.test.ts`**
Add a new `describe('findLandedAtDivergence', ...)` block (this file currently only imports `findViolations`; add `findLandedAtDivergence` to the import) with two tests using the file's existing `todo()` helper:
```ts
describe('findLandedAtDivergence', () => {
  test('landed-satisfies: landedAt set, no [LAND] child, ahead=0 → []', () => {
    const epic = todo({ id: 'e1', title: '[EPIC] shipped', status: 'done', kind: 'epic', landedAt: '2026-07-20T00:00:00Z' });
    const aheadOf = (epicId: string) => (epicId === 'e1' ? 0 : undefined);
    expect(findLandedAtDivergence([epic], aheadOf)).toEqual([]);
  });

  test('stranded-still-violates: landedAt set, no [LAND] child, ahead=3 → one violation', () => {
    const epic = todo({ id: 'e1', title: '[EPIC] stranded', status: 'done', kind: 'epic', landedAt: '2026-07-20T00:00:00Z' });
    const aheadOf = (epicId: string) => (epicId === 'e1' ? 3 : undefined);
    const v = findLandedAtDivergence([epic], aheadOf);
    expect(v).toHaveLength(1);
    expect(v[0].kind).toBe('landed-at-divergence');
    expect(v[0].todoId).toBe('e1');
  });
});
```

**3. `src/services/__tests__/epic-landed-at-equivalence.test.ts`**
The existing fixture test at line 136-143 ("divergent: epic has landedAt set but no done land-leaf child → flagged") calls `findLandedAtDivergence([epic, land])` with **no** `aheadOf` arg, which under the new logic defaults `ahead=0` → **no violation** — contradicting its own assertion. This test encodes the old symmetric semantics being fixed here, so it must be updated to pass an `aheadOf` returning `>0` to keep asserting the still-valid "genuinely stranded" case:
```ts
it('divergent: epic has landedAt set but branch still ahead>0 (stranded) → flagged', () => {
  const epic = baseTodo({ id: 'epic-6', kind: 'epic', title: 'epic', landedAt: '2026-01-02T00:00:00.000Z' });
  const land = baseTodo({ id: 'land-6', kind: 'land', title: 'land', parentId: 'epic-6', status: 'planned' });
  const violations = findLandedAtDivergence([epic, land], (id) => (id === 'epic-6' ? 2 : undefined));
  expect(violations).toHaveLength(1);
  expect(violations[0].kind).toBe('landed-at-divergence');
  expect(violations[0].todoId).toBe('epic-6');
});
```
Also add one new adjacent case proving the "landed satisfies" direction from this same file's fixture style (landedAt set, no land child, **no** ahead lookup passed / ahead not >0 → `[]`):
```ts
it('landed epic with no [LAND] child and ahead=0 (post-cutover shape) → no divergence', () => {
  const epic = baseTodo({ id: 'epic-7', kind: 'epic', title: 'epic', landedAt: '2026-01-02T00:00:00.000Z' });
  expect(findLandedAtDivergence([epic])).toEqual([]);
});
```
