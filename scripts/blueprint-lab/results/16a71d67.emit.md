## Blueprint: Single `resolvedPort()` + config.json port key

### Problem
The API port is parsed independently in **11 places**, all with the identical literal `parseInt(process.env.PORT || '9002', 10)` (or `??`), plus one variant (`process.env.PORT || 9002` in `bin/mermaid-collab.ts`, out of scope — see below). None of them fall back to `~/.mermaid-collab/config.json`, unlike every other config value in `src/services/config-file.ts` (`getConfig`/`getSecret`). This means a process launched without the `PORT` env var (e.g. a Dock-launched desktop sidecar — the exact scenario `config-file.ts:16-18` already documents fixing for other keys) cannot discover a non-default port.

`src/services/config-file.ts` already implements the precedence machinery (`getConfig`: env → config.json → fallback) that every other config key uses. Add one function there and point all duplicated sites at it.

### Change 1 — add `resolvedPort()` to `src/services/config-file.ts`
Insert after `getSecret()` (after line 65), before `getConfigEntries()`:

```ts
const PORT_KEY = 'PORT';

/**
 * Resolve the API server's port for client-side callers (MCP tool handlers,
 * BindingReconciler, lane registration) that need to reach this server's own
 * HTTP API. Precedence: process.env.PORT → config.json "PORT" → 9002 — the
 * same env-first precedence as getConfig(), so a process launched without
 * PORT (e.g. a Dock-launched sidecar) still resolves a Settings-configured
 * custom port instead of always falling through to the 9002 default.
 */
export function resolvedPort(): number {
  const raw = getConfig(PORT_KEY, '9002') ?? '9002';
  const port = parseInt(raw, 10);
  return Number.isNaN(port) ? 9002 : port;
}
```
