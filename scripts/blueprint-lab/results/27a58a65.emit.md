## Blueprint: Pin-as-conductor-target control in the mission rail + store action

### Context (read, not guessed)

- **Backend already round-trips the pin** — `src/routes/supervisor-routes.ts:896-938` implements `GET /api/supervisor/conductor?project=` (returns `{ project, enabled, targetMissionId }`) and `POST /api/supervisor/conductor` (body `{ project, enabled?, targetMissionId? }`, UPDATE-only, either field independently settable). Verified round-trip in `src/routes/__tests__/conductor-target-route.test.ts`. **No backend change needed.**
- **The mission rail** is `ui/src/components/supervisor/bridge/inspector/MissionDetailPanel.tsx`, which renders `MissionDetail` (defined in `ui/src/components/supervisor/bridge/rail/missionShared.tsx:538-725`) for the selected mission, plus a switcher list of "other missions". `MissionDetail`'s controls cluster (`missionShared.tsx:607-630`) already has `Approve` / `Activate` / an "● active" badge / `Drop` / `Edit` / `Delete` `MiniButton`s wired to `useSupervisorStore` actions (`activateMission`, `approveMission`, `abandonMission`, `updateMission`, `deleteMission` — all declared `supervisorStore.ts:583-590`, implemented `supervisorStore.ts:972-1018`, all following the shape `(serverId, project, todoId, ...) => Promise<MissionSummary[]>` via the shared `invoke(serverId, path, method, body)` helper at `supervisorStore.ts:376-391`).
- The conductor target is **project-scoped**, not mission-scoped, so it can't reuse the mission-array-returning action shape. The closest existing precedent for a project-scoped GET/POST-cached-by-project pair is `loadCoverage`/`coverageByProject` (`supervisorStore.ts:1281-1284`, state field `supervisorStore.ts:659`) — same shape I'll follow: `Record<string, T>` state + a fetch action that `set()`s it.
- There is already an ad-hoc conductor hook, `ui/src/components/supervisor/bridge/useConductorEnabled.ts`, but it bypasses the store entirely (calls `window.mc.invokeOnServer('local', ...)` directly, hardcoding server `'local'`) — inconsistent with how `MissionDetail` already gets its actions (through the store, parameterized by `serverId`). Don't extend that hook; add the new store actions instead, matching the mission actions' pattern, and a new rail-local hook (mirroring `ui/src/components/supervisor/bridge/rail/useMissions.ts`) that polls it.
- `MissionSummary.node.id` (`supervisorStore.ts:298-299`) is the mission's `todoId` and is what `MissionDetail` calls `view.missionId` (`missionShared.tsx:745`, `764`) — the same id space the pin (`targetMissionId`) is keyed on.

  ```ts

  ```

- Implement both right after `removeMissionCriterion`'s body (after line 1018), following the `loadCoverage` GET pattern and the mission actions' `invoke` pattern:
  ```ts
  fetchConductorTarget: async (serverId, project) => {
    const res = await invoke(serverId, `/api/supervisor/conductor?project=${encodeURIComponent(project)}`, 'GET');
    if (!res?.ok) return get().conductorTargetByProject[project] ?? null; // keep prior on failure
    const targetMissionId = res.body?.targetMissionId ?? null;
    set((state) => ({ conductorTargetByProject: { ...state.conductorTargetByProject, [project]: targetMissionId } }));
    return targetMissionId;
  },

  setConductorTarget: async (serverId, project, targetMissionId) => {
    const res = await invoke(serverId, '/api/supervisor/conductor', 'POST', { project, targetMissionId });
    if (!res?.ok) return get().conductorTargetByProject[project] ?? null;
    const next = res.body?.targetMissionId ?? null;
    set((state) => ({ conductorTargetByProject: { ...state.conductorTargetByProject, [project]: next } }));
    return next;
  },
  ```

**2. `ui/src/components/supervisor/bridge/rail/useConductorTarget.ts` (new file)** — mirrors `useMissions.ts`'s fetch+poll shape exactly, but for the single project-scoped pin value:
```ts
import { useEffect, useState } from 'react';
import { useSupervisorStore } from '@/stores/supervisorStore';

export function useConductorTarget(serverId: string, project: string) {
  const fetchConductorTarget = useSupervisorStore((s) => s.fetchConductorTarget);
  const setConductorTargetAction = useSupervisorStore((s) => s.setConductorTarget);
  const [targetMissionId, setTargetMissionId] = useState<string | null>(null);
  const [busy, setBusy] = useState(false);

  useEffect(() => {
    let alive = true;
    const load = async () => {
      const next = await fetchConductorTarget(serverId, project);
      if (alive) setTargetMissionId(next);
    };
    void load();
    const timer = setInterval(load, 15000);
    return () => { alive = false; clearInterval(timer); };
  }, [serverId, project, fetchConductorTarget]);

  const setTarget = async (missionId: string | null) => {
    setBusy(true);
    try {
      setTargetMissionId(await setConductorTargetAction(serverId, project, missionId));
    } finally {
      setBusy(false);
    }
  };

  return { targetMissionId, setTarget, busy };
}
```
