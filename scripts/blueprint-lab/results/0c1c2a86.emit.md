## Blueprint: `approveMission` store action + Approve button in mission detail view

### Context confirmed by reading the code

- **Backend REST route already exists and is wired**: `src/routes/supervisor-routes.ts:299-309` — `POST /api/supervisor/missions/approve` validates `{project, todoId}`, calls `handleMissionTool('approve_mission', body)`. Nothing to change server-side.
- **MCP tool contract**: `src/mcp/mission-tools.ts:29` — `approve_mission` takes `{project, todoId, approvedBy?}`, returns the updated mission + activated constraints.
- **Store pattern to mirror**: `ui/src/stores/supervisorStore.ts:971-975` (`activateMission`) — every mission mutation is `invoke(serverId, path, method, body)` → on `!res?.ok` return `[]` → else `return get().fetchMissions(serverId, project)`.
- **Status vocabulary already ships `unapproved`**: `ui/src/stores/supervisorStore.ts:296` (`MissionStatus`), rendered via `STATUS_LABEL`/`STATUS_STYLE`/`statusTooltip` in `ui/src/components/supervisor/bridge/rail/missionShared.tsx:38-72`. `missionView(m).status` (`missionShared.tsx:740`) already derives this from `m.rollup?.status` — no new derived field needed.
- **Target component**: `MissionDetail` in `ui/src/components/supervisor/bridge/rail/missionShared.tsx:538-714`. It already reads several mutators via `useSupervisorStore` (lines 553-559) and has a "Controls cluster" button row at lines 601-619 (`Activate`/`Drop`/`Edit`/`Delete`) using the shared `run()` helper (lines 563-566) and `MiniButton` (lines 97-123).

### Changes

**1. `ui/src/stores/supervisorStore.ts`**

- Add to the store interface, directly after `activateMission` (line 583):
  ```ts
  approveMission: (serverId: string, project: string, todoId: string) => Promise<MissionSummary[]>;
  ```
- Add the implementation directly after `activateMission`'s implementation (after line 975, before `updateMission`):
  ```ts
  approveMission: async (serverId, project, todoId) => {
    const res = await invoke(serverId, '/api/supervisor/missions/approve', 'POST', { project, todoId });
    if (!res?.ok) return [];
    return get().fetchMissions(serverId, project);
  },
  ```

**2. `ui/src/components/supervisor/bridge/rail/missionShared.tsx`**

- In `MissionDetail`, add a selector alongside the existing ones (after line 553):
  ```ts
  const approveMission = useSupervisorStore((s) => s.approveMission);
  ```
- In the "Controls cluster" div (lines 601-619), add an Approve button gated on `view.status === 'unapproved'`, placed before the `Activate` button so it's the first/primary action when present:
  ```tsx
  {view.status === 'unapproved' && (
    <MiniButton
      onClick={() => void run(() => approveMission(serverId, project, view.missionId!))}
      disabled={busy}
      tone="primary"
      title="Approve this forged mission — activates it and ratifies its constitution"
      testid="mission-approve-btn"
    >
      Approve
    </MiniButton>
  )}
  ```
  No confirm dialog — mirrors `Activate`'s no-confirm path for the non-terminal case; approval is not destructive.

- Any change to the already-shipped REST route or MCP tool.
