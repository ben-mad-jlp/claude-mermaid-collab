## Blueprint: Live-evidence harness — two consecutive sweeps over the self/live project

### Context

`runLandedEpicSweep` (`src/services/landed-epic-sweep.ts:188-228`) is the composed hygiene pass — `reconcileLandedEpics` → yield → `gcEpicBranches` → yield → `promoteQueuedMissions` (+`syncMissionSubscription`) — that the real orchestrator invokes every tick in production, forced, against every watched project (`src/services/orchestrator-live.ts:394,601-604`). It is throttled by `shouldRunLandedEpicSweep`/`LANDED_EPIC_SWEEP_INTERVAL_MS` (`landed-epic-sweep.ts:19-28`), but `{force:true}` bypasses that.

Existing unit coverage (`src/services/__tests__/landed-epic-sweep-throttle.test.ts:57-92`, `src/services/__tests__/landed-epic-sweep.test.ts`) only exercises the function against synthetic scratch projects with fake `GitProbe`/`BranchGcRunner`. Existing `scripts/live-*.ts` harnesses (e.g. `scripts/live-conductor-pin-evidence.ts`) go the opposite direction — they *refuse* to run against the real collab project (`isSelfProject`, `deploy-service.ts:106-113`, checked at `live-conductor-pin-evidence.ts:138-141`) and instead spin up a disposable scratch git repo.

Neither proves the thing this leaf asks for: does `runLandedEpicSweep`, run twice back-to-back against the **real self/live project** (this actual `mermaid-collab` checkout, with its actual `.collab` todo/mission data and actual epic branches), converge — i.e. is the second consecutive pass a no-op relative to the first? That's the live-evidence gap. This is intentionally the inverse precondition of the other `live-*` scripts: assert `isSelfProject(project) === true`, not `false`, since observing real sweep behavior on real data is the point.

### Change shape

**New file: `scripts/live-landed-epic-sweep-evidence.ts`**

Modeled directly on `scripts/live-conductor-pin-evidence.ts`'s structure (assertion helper, evidence blob, JSON write, exit code) but in-process (no HTTP/`BASE_URL` — `runLandedEpicSweep` is a plain async service function, not exposed via any supervisor route; confirmed no route references it in `src/routes/`), and read-mostly against the real repo root rather than a `mkdtempSync` scratch project:

```ts
import { runLandedEpicSweep, type RunLandedEpicSweepResult } from '../src/services/landed-epic-sweep';
import { isSelfProject } from '../src/services/deploy-service';
import { mkdirSync, writeFileSync } from 'node:fs';
import { join } from 'node:path';

const project = process.cwd();

interface Assertion { name: string; ok: boolean; detail?: string; }
interface SweepEvidenceBlob {
  startedAt: number;
  finishedAt: number;
  project: string;
  passOne: RunLandedEpicSweepResult;
  passTwo: RunLandedEpicSweepResult;
  assertions: Assertion[];
  verdict: 'PASS' | 'FAIL';
}

async function main() {
  const startedAt = Date.now();
  const assertions: Assertion[] = [];
  const check = (name: string, ok: boolean, detail = ''): void => { assertions.push({ name, ok, detail: detail || undefined }); };

  check('running against the real self/live project', isSelfProject(project), `project=${project}`);

  const passOne = await runLandedEpicSweep(project, { force: true });
  const passTwo = await runLandedEpicSweep(project, { force: true });

  check('pass two reconciled nothing new (idempotent)', passTwo.reconcile.reconciled.length === 0, JSON.stringify(passTwo.reconcile));
  check('pass two deleted no additional branches', passTwo.gc.deleted.length === 0, JSON.stringify(passTwo.gc));
  check('pass two promoted no additional missions', passTwo.promoted.length === 0, JSON.stringify(passTwo.promoted));
  check('pass two flagged set is a subset of pass one flagged (no new discoveries)',
    passTwo.gc.flagged.every((b) => passOne.gc.flagged.includes(b)),
    `passOne.flagged=${JSON.stringify(passOne.gc.flagged)} passTwo.flagged=${JSON.stringify(passTwo.gc.flagged)}`);

  const finishedAt = Date.now();
  const fail = assertions.filter((a) => !a.ok).length;
  const verdict: 'PASS' | 'FAIL' = fail === 0 ? 'PASS' : 'FAIL';
  const blob: SweepEvidenceBlob = { startedAt, finishedAt, project, passOne, passTwo, assertions, verdict };

  const evidenceDir = join(process.cwd(), 'docs', 'evidence');
  mkdirSync(evidenceDir, { recursive: true });
  writeFileSync(join(evidenceDir, `live-landed-epic-sweep-evidence-${finishedAt}.json`), JSON.stringify(blob, null, 2));
  console.log(JSON.stringify(blob));
  process.exit(verdict === 'PASS' ? 0 : 1);
}

await main();
```

Key points a reviewer should check:
- Both calls pass `{ force: true }` (bypasses `shouldRunLandedEpicSweep`'s 5-min throttle, `landed-epic-sweep.ts:200`) so the second pass isn't silently skipped and rendered a fake no-op.
- No injected `probe`/`runner` — this deliberately exercises `makeGitProbe`/`makeBranchGcRunner`'s real defaults (`landed-epic-sweep.ts:46,150,113-124`) against the actual repo, which is what makes it "live evidence" rather than a unit test.
- `isSelfProject(project)` is asserted **true** (inverse of `live-conductor-pin-evidence.ts:138-141`'s refusal), recorded as an assertion, not a thrown guard — so a FAIL verdict is visible in the evidence blob even if run from the wrong cwd.

### Out of scope
- No change to `runLandedEpicSweep`, `reconcileLandedEpics`, or `gcEpicBranches` themselves.
- No new HTTP route — this stays an in-process CLI script like the other `live:*` entries.
- No scratch-project isolation — targeting the real self project is the explicit point of this leaf.
- No wiring into `test:ci`/CI — it's a manually-run evidence harness, same tier as `live:conductor-pin-evidence`.
