## Blueprint: Corpus builder — mine ≥10 historical landed leaves spanning ≥3 leafKinds with real base..HEAD diffs

### Context confirmed by inspection

- `DiffLeafKind` = `'feature' | 'fix' | 'refactor' | 'test' | 'infra'` (`src/services/diff-contract.ts:14`), independent of the todo's own free-form `type: string | null` field (`src/services/todo-store.ts:90`) — so leafKind for this corpus must be derived some other way, not read off the todo row.
- `CONTRACT_STRICTNESS_MATRIX` (`src/services/diff-contract.ts:69-76`) and `validateContractForKind` (`diff-contract.ts:99-111`) are the thing this corpus exists to calibrate against real diffs (dormant v2 contract, not yet wired — see project memory `typed-diff-contract-dormant`).
- Every landed leaf commit in this repo's own history carries a `Collab-Todo: <uuid>` trailer (verified: `git log -1 93150d82` shows `Collab-Todo: 16de47a7-99e1-4539-9d4d-6faedf4c5ddc`; `git log --grep="^Collab-Todo:" -100` returns 100 real hits on this branch alone). Commit subjects follow conventional-commit prefixes (`feat:`, `fix:`, `test:`, `chore:`) which map cleanly onto `DiffLeafKind` (`feat`→feature, `fix`→fix, `test`→test, `refactor`→refactor, `chore`/`build`→infra). Confirmed real examples exist for feat (`c2e6f88f`), fix (`cf490efb`, `465d8237`, `50e91223`), test (`0c1d3816`, `d9e2e66e`), and infra/chore (`c504ed82`, `5b116a56`) — i.e. real commits covering ≥4 of the 5 kinds already exist on this branch, comfortably clearing the ≥3-kind bar.
- No existing "corpus"/fixture directory for historical leaf diffs exists anywhere in `src/` or `scripts/`. The one structural precedent is `scripts/reviewer-lab/cases.ts` (a `Case[]` array of **synthetic** base/after file maps) — useful as a shape precedent but NOT reusable here since this leaf requires **real** git history, not fabricated cases.
- `scripts/test-backend.ts` (the enforced backend test gate) scans every `*.test.tsx?` under `src/` that imports `bun:test` — `scripts/__tests__/*.test.ts` (e.g. `parent-epic-under-mission.test.ts`) is NOT in that scan. So the mechanically-checked test for this corpus must live under `src/services/__tests__/` to be gate-covered.

### Change shape

**1. `scripts/diff-contract-corpus/build-corpus.ts`** (new) — a read-only mining script, run manually (`bun run scripts/diff-contract-corpus/build-corpus.ts`), NOT wired into any pipeline:
- Shells out to `git log --format='%H%x1f%s' master` (via `Bun.spawnSync` / `child_process.execSync`, read-only — no `git` mutation commands).
- For each commit, runs `git log -1 --format=%B <sha>` and regex-matches `/^Collab-Todo: ([0-9a-f-]{36})$/m` to get the todo uuid; skips commits without the trailer.
- Dedupes by todoId (first master-reachable commit wins).
- Classifies `leafKind: DiffLeafKind` from the subject's conventional-commit prefix (`feat`→`feature`, `fix`→`fix`, `test`→`test`, `refactor`→`refactor`, everything else, e.g. `chore`/`build`→`infra`); skip commits whose prefix doesn't map.
- For each selected commit computes: `id` (leading-8-hex slice of the todo uuid, per project's `short_id_convention`), `sha`, `parentSha` (`` `${sha}^` ``), `subject`, `leafKind`, `filesChanged` (`git show --stat=200 --format= <sha>`, parsed to a string array), `diff` (`git show --format= <sha>`, the real unified diff text for that leaf).
- Selects ≥10 distinct todoIds spanning ≥3 distinct `leafKind` values, and writes them as a JSON array to `scripts/diff-contract-corpus/corpus.json`.
- Exports a pure `buildCorpus(shas: {sha, todoId, subject}[]): CorpusCase[]` classification/extraction function so it's unit-testable without shelling out in the test itself.

**2. `scripts/diff-contract-corpus/corpus.ts`** (new) — the citable, imported symbol:
```ts
export interface CorpusCase {
  id: string; sha: string; parentSha: string; subject: string;
  leafKind: DiffLeafKind; filesChanged: string[]; diff: string;
}
export function loadCorpus(): CorpusCase[] // reads ./corpus.json (bundled JSON import), validates shape, throws on malformed entries
```
Imports `DiffLeafKind` from `../../src/services/diff-contract.ts` — the ONLY coupling point to the diff-contract module (no changes to `diff-contract.ts` itself).

**3. `scripts/diff-contract-corpus/corpus.json`** (new, checked in) — the generated data: ≥10 entries, ≥3 distinct `leafKind` values, real shas/diffs from this repo's own git history (per the confirmed examples above).

**4. `src/services/__tests__/diff-contract-corpus.test.ts`** (new) — gate-covered by `test:backend`:
- imports `loadCorpus` from `../../../scripts/diff-contract-corpus/corpus`
- asserts `loadCorpus().length >= 10`
- asserts `new Set(loadCorpus().map(c => c.leafKind)).size >= 3`
- asserts every case has a non-empty `diff` string and a `sha` matching `/^[0-9a-f]{7,40}$/`

**5. `package.json`** (edit) — add a convenience script `"diff-contract:corpus": "bun run scripts/diff-contract-corpus/build-corpus.ts"` next to the existing `test:backend` entry (`package.json:26-27`).

- Fetching diffs via any live LLM call — this is pure `git log`/`git show` extraction.
- Any change to `src/services/diff-contract.ts` itself.
