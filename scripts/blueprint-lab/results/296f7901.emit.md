## Fix: `deriveCheapMissionStatus` — key `converged` off criteria, not epics

### Problem
`deriveCheapMissionStatus` (mission-store.ts:960-968) derives `converged` from
`epics.every(e => e.status === 'done')`, ignoring acceptance criteria — disagreeing
with the rollup's own `converged` flag (`criteria.length > 0 && capMet === criteria.length`,
mission-store.ts:1168) in both directions.

### Change 1 — `deriveCheapMissionStatus` signature + logic (mission-store.ts:960-968)
Add a third param `criteria: readonly { met: boolean }[]` and key `converged` off it,
mirroring the non-vacuous `criteria.length > 0 && ...every(met)` gate already used at
mission-store.ts:945 (`deriveMissionStatus`) and :1168 (cheap rollup):

```ts
export function deriveCheapMissionStatus(
  m: Pick<MissionRow, 'abandonedAt' | 'awaitingApprovalSince'>,
  epics: readonly { status: string }[],
  criteria: readonly { met: boolean }[],
): MissionStatus {
  if (m.abandonedAt != null) return 'abandoned';
  if (m.awaitingApprovalSince != null) return 'unapproved';
  if (criteria.length > 0 && criteria.every((c) => c.met)) return 'converged';
  return 'building';
}
```
`epics` becomes unused by the body but keep the param (both call sites already have the
value in hand; dropping it would be a wider signature churn than this fix needs — update
the doc comment at :949-959 instead, since its "proxy (all epics done)" description is now
wrong).

### Change 2 — thread criteria through both call sites in `listMissions` (mission-store.ts:1117-1180)
Today `listCriteria(project, node.id)` (currently line 1156) runs AFTER the mission/status
is derived (line 1139) — too late for call site 1 to see criteria. Reorder: hoist the
`listCriteria` call to right after `epicsForNode` is built (before the `raw`/`mission`
block), store it once, and reuse it for both the mission-status call (was line 1139) and
the rollup's cheap-path call (was line 1170), removing the now-redundant second
`listCriteria` call at the old line 1156:

```ts
const epicsForNode = all.filter(...).map(...);
const criteriaForNode = listCriteria(project, node.id);
const raw = withFacts ? getMission(project, node.id) : getMissionRaw(project, node.id);
let mission = raw && !withFacts
  ? { ...raw, status: deriveCheapMissionStatus(raw, epicsForNode, criteriaForNode) }
  : raw;
...
const epics = epicsForNode;
const criteria = criteriaForNode;
...
status: mission.status ?? deriveCheapMissionStatus(mission, epics, criteria),
```
Net effect: `listCriteria` now runs once per root node unconditionally (previously it ran
once per node that survived the archived/session filters) — an indexed per-mission lookup,
not a facts scan, so this stays inside the "no `collectMissionStatusFacts`" cheap-path
contract the function's doc comment (mission-store.ts:1108-1116) promises.

1. Zero epics, all criteria met → `status: 'converged'` (regression for aad41fd5: 6/6 met,
   mech 0/0 must NOT read `'building'`).
2. All epics done, one criterion unmet → `status` NOT `'converged'` (regression for
   b90bfa21: 6/7 must NOT read `'converged'`).

   met) — the bug's core symptom was these two disagreeing.
5. Terminal precedence still wins: an abandoned mission with all criteria met still reads
   `'abandoned'`, not `'converged'` (abandonedAt checked before the criteria gate).
