## Blueprint: Seed specJson at blueprint persist and route reattach through restoreEditableBlueprint

### Context

`src/services/worker-ledger.ts` already has the durable `leaf_blueprint` table with `specJson`/`specRev` columns, plus accessors `recordLeafBlueprint` (upserts, only overwrites `specJson`/`specRev` when explicitly passed), `restoreEditableBlueprint` (splices an edited contract back over the base blueprint's json fence, falls back to verbatim base), `editContractField`, and `editLeafRequirement` (both lazily seed `specJson` from the base blueprint contract on first edit).

`src/services/leaf-executor.ts` is where the blueprint node's success is persisted and where reattach reads it back, but it currently:

1. Calls `deps.persistBlueprintBase?.({ project, leafId: leaf.id, epicBaseSha: deps.epicBaseSha })` at `src/services/leaf-executor.ts:2518` with no `specJson`/`specRev` — so the durable row's `specJson` stays `null` until (if ever) a human/editor calls `editContractField`/`editLeafRequirement`.
2. Wires `restoreBlueprint: (leafId) => getLatestSuccessfulNodeOutput(leafId, 'blueprint')` at `src/services/leaf-executor.ts:3504` — this reads the RAW node output directly, bypassing `restoreEditableBlueprint` entirely, so a reattach (`src/services/leaf-executor.ts:2477`) can never pick up an edited contract even if one exists.

### Change 1 — seed `specJson` at persist time

**File:** `src/services/leaf-executor.ts`

At the top, add the diff-contract helpers to the existing import block. There is no existing import from `./diff-contract` in this file; add one near the other local-module imports (e.g. after line 30's `split-decision` import):

```ts
import { parseDiffContract, renderContract } from './diff-contract';
```

At `src/services/leaf-executor.ts:2514-2519` (the "G8: Record the blueprint base SHA" block, guarded by `if (!reattach && !inRunCarry)`), replace the bare call with one that also seeds `specJson`/`specRev` by parsing `bp.text` (the blueprint node's raw final-message output, which is the same source `editContractField`/`editLeafRequirement` already fall back to via `getLatestSuccessfulNodeOutput`):

```ts
if (!reattach && !inRunCarry) {
  const seedContract = parseDiffContract(bp.text);
  deps.persistBlueprintBase?.({
    project,
    leafId: leaf.id,
    epicBaseSha: deps.epicBaseSha,
    ...(seedContract ? { specJson: renderContract(seedContract), specRev: 0 } : {}),
  });
}
```

When `bp.text` doesn't carry a valid v2 contract (e.g. legacy v1 blueprint output), `parseDiffContract` returns `null` and the call falls back to today's behavior (no `specJson`/`specRev` passed, `recordLeafBlueprint`'s `CASE WHEN` preserves whatever's already in the row) — this is a pure addition, never a regression.

Update the `persistBlueprintBase` deps type at `src/services/leaf-executor.ts:421` to accept the new optional fields, matching `recordLeafBlueprint`'s parameter shape in `src/services/worker-ledger.ts:528`:

```ts
persistBlueprintBase?: (e: { project: string; leafId: string; epicBaseSha?: string | null; specJson?: string | null; specRev?: number | null }) => void;
```

No change needed at the wiring site `src/services/leaf-executor.ts:3478` (`persistBlueprintBase: recordLeafBlueprint`) — `recordLeafBlueprint`'s signature already accepts `specJson`/`specRev`.

### Change 2 — route reattach through `restoreEditableBlueprint`

**File:** `src/services/leaf-executor.ts`

Add `restoreEditableBlueprint` to the existing worker-ledger import at `src/services/leaf-executor.ts:47`:

```ts
import { recordNode, setLeafInflight, clearLeafInflight, recordLeafResume, markLeafMerged, getLatestSuccessfulNodeOutput, getLeafResume, clearLeafResume, recordEpicBaseGate, getEpicBaseGate, recordLeafBlueprint, getLeafBlueprint, clearLeafBlueprint, recordLeafResumeDecision, restoreEditableBlueprint } from './worker-ledger';
```

Change the `restoreBlueprint` wiring at `src/services/leaf-executor.ts:3504` from:

```ts
restoreBlueprint: (leafId) => getLatestSuccessfulNodeOutput(leafId, 'blueprint'),
```

to:

```ts

```

`restoreEditableBlueprint` already internally calls `getLatestSuccessfulNodeOutput(leafId, 'blueprint')` as its base (`src/services/worker-ledger.ts:568`) and only diverges when `getLeafBlueprint(leafId).specJson` is non-null, in which case it splices the edited contract's rendered fence over the base's trailing json block. So this change is strictly additive for the reattach path at `src/services/leaf-executor.ts:2477` (`deps.restoreBlueprint?.(leaf.id)`): unedited leaves get byte-identical behavior to today; edited leaves now reattach the EDITED plan instead of the stale raw one.
