### Fixture setup (one `beforeEach`-built scenario, reused by both tests)

**A. Queue-promotion / session-starvation pair (exercises steps 1 & 5's ordering)**
- `mission1 = createTodo(project, { allowOrphan:true, ownerSession:'s1', title:'[MISSION] m1', kind:'mission' })`; `upsertMission(project, mission1.id)`; `enqueueMission(project, mission1.id)` — this leaves it `active:false, queuePos:1, awaitingApprovalSince:null` (approved+queued+non-terminal), i.e. exactly `promoteQueuedMissions`'s candidate shape (`mission-store.ts:572-580`).

**B. `landedAtDivergence` violation (exercises step 2)**
- `epicDiv = createTodo(project, { allowOrphan:true, ownerSession:'s1', title:'[EPIC] div', kind:'epic', status:'planned' })`
- `land = createTodo(project, { allowOrphan:true, ownerSession:'s1', title:'[LAND] div → master', parentId: epicDiv.id, kind:'land', status:'planned' }); await completeTodo(project, land.id, 'accepted')` — done `[LAND]` child, but never call `stampEpicLandedAt` on `epicDiv`, so `landedAt` stays null → matches the `hasDoneLand && t.landedAt == null` branch of `findLandedAtDivergence` (`invariant-check.ts:171-180`).

**C. Stateful branch fake for GC fields (exercises steps 3 & 4)** — three epics:
- `epicDel = createTodo(...)` → branch state `{ exists:true, ahead:0 }`, deletable.
- `epicFlag = createTodo(...)` → branch state `{ exists:true, ahead:2 }`.
- `epicRemain = createTodo(...)` → branch state `{ exists:true, ahead:0 }`, but its `deleteBranch` call is made to fail (returns `false`) so it survives GC as `skipped`.

Build a **mutable** branch map (not a static closure) so the post-GC re-probe (step 4) actually observes step 3's mutation — this is the part that makes the test meaningfully hermetic rather than tautological:
```ts
const branchState = new Map<string, { exists: boolean; ahead: number }>([
  [epicBranchName(epicDel.id), { exists: true, ahead: 0 }],
  [epicBranchName(epicFlag.id), { exists: true, ahead: 2 }],
  [epicBranchName(epicRemain.id), { exists: true, ahead: 0 }],
]);
const probe: GitProbe = (b) => {
  const s = branchState.get(b);
  return s
    ? { exists: s.exists, ahead: s.ahead, behind: 0, mergeable: true }
    : { exists: false, ahead: null, behind: null, mergeable: null };
};
const runner: BranchGcRunner = {
  revParse: (b) => (branchState.get(b) ? 'deadbeef' : null),
  deleteBranch: (b) => {
    if (b === epicBranchName(epicRemain.id)) return false; // simulate delete failure
    branchState.delete(b);
    return true;
  },
};
```

### Test 1 — "measures all five composed fields correctly over the synthetic fixture"
Call `const result = runSweepMeasurement(project, { probe, runner, baseRef: 'master' })` and assert:
- `result.promoted).toContain(mission1.id)` — proves step 1 fired.
- `result.landedAtDivergence.ids).toContain(epicDiv.id)` and `.count` reflects it — proves step 2.
- `result.gcDeleted).toContain(epicBranchName(epicDel.id))` — proves step 3 delete path.
- `result.gcFlagged).toContain(epicFlag.id)` — proves step 3 flag path.
- `result.fullyOnMasterBranchesRemaining).toContain(epicBranchName(epicRemain.id))` and `.not.toContain(epicBranchName(epicDel.id))` — proves step 4 genuinely re-probes post-GC state (the deleted branch is gone from the remaining list; the failed-delete branch is still there).
- `result.sessionsZeroActiveWithQueuedApproved).not.toContain('s1')` — proves the step-1-before-step-5 ordering documented at `sweep-measurement.ts:50-53`: `mission1` got promoted to active in step 1, so by the time step 5 runs, session `s1` no longer has a zero-active-with-queued-approved condition.

### Test 2 — "second consecutive run is idempotent: no repeat mutation, stable divergence/flag reporting"
Call `runSweepMeasurement` a second time with the **same** `probe`/`runner`/project (no fixture rebuild) and assert:
- `second.promoted).toEqual([])` — `mission1` is already active, no longer a promotion candidate.
- `second.gcDeleted).toEqual([])` — `epicDel`'s branch is already absent from `branchState`, so it's `skipped` not re-deleted (`landed-epic-sweep.ts:161`, `e.exists` false).
- `second.gcFlagged).toEqual(first.gcFlagged)` — `epicFlag` (ahead>0) is unaffected, stable across runs.
- `second.fullyOnMasterBranchesRemaining).toEqual(first.fullyOnMasterBranchesRemaining)` — `epicRemain` still fails to delete, so the remaining-list is byte-for-byte stable.
- `second.landedAtDivergence).toEqual(first.landedAtDivergence)` — the sweep never repairs divergence, so the same violation reports unchanged both passes.
- `second.sessionsZeroActiveWithQueuedApproved).toEqual([])` — stays empty (session `s1` now permanently has an active mission).
