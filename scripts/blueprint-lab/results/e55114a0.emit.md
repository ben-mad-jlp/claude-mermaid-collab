## Blueprint: Honor the pin in `runConductorPass` with no-fallback and lazy auto-clear

### Context

`src/services/supervisor-store.ts:483-493` already persists an explicit per-project conductor target (`getConductorTargetMission` / `setConductorTargetMission`, backed by the `watched_project.conductorTargetMissionId` column). Nothing reads it yet: `runConductorPass` in `src/services/conductor-pass.ts:91-105` always picks "the first `mission.active` mission that qualifies" via `listMissions(project).filter((m) => m.mission.active)`, which — per the store's own doc comment — "cannot disambiguate: multiple missions can be active at once."

This leaf wires the pin into that target-resolution block with two properties:

1. **No-fallback** — if a pin is set, the pinned mission is the *only* candidate for this pass. If it isn't currently actionable (unapproved, still awaiting approval), the pass reports `no-actionable-mission` — it must never silently drive some other active mission instead, or the pin stops disambiguating anything.
2. **Lazy auto-clear** — if the pinned mission is *stale* (its node is gone, or its derived status is terminal — `abandoned`/`converged`), the pin itself is dead. Rather than running a separate sweep to catch this, `runConductorPass` clears it the moment it's noticed (via `setConductorTargetMission(project, null)`) and falls through to today's default first-active-mission scan for that same pass.

### Exact change

**File: `src/services/conductor-pass.ts`**

1. Extend the import from `./supervisor-store.js` (line 11) to add `getConductorTargetMission, setConductorTargetMission`:

2. Replace the target-resolution block at `src/services/conductor-pass.ts:96-105` (currently: declare `target`, loop over `listMissions(project).filter((m) => m.mission.active)`, `if (!target) return ...`) with:

```ts
  let target: { summary: ReturnType<typeof listMissions>[number]; row: NonNullable<ReturnType<typeof getMission>> } | undefined;
  const pinnedMissionId = getConductorTargetMission(project);
  if (pinnedMissionId) {
    const pinnedRow = getMission(project, pinnedMissionId);
    const isStale = !pinnedRow || ['abandoned', 'converged'].includes(pinnedRow.status ?? '');
    if (isStale) {
      // Lazy auto-clear: only checked (and cleared) when a pass actually looks for it — no
      // separate sweep. Falls through to the default scan below for THIS pass.
      setConductorTargetMission(project, null);
    } else {
      const pinnedSummary = listMissions(project).find((m) => m.node.id === pinnedMissionId);
      if (pinnedSummary && pinnedRow.awaitingApprovalSince == null && pinnedRow.status != null &&
          !['unapproved', 'abandoned', 'converged'].includes(pinnedRow.status)) {
        target = { summary: pinnedSummary, row: pinnedRow };
      }
      // No-fallback: a pin names ONE mission. If it isn't actionable right now, that IS the
      // answer for this pass — never fall back to scanning other active missions.
      if (!target) return { ran: false, reason: 'no-actionable-mission' };
    }
  }
  if (!target) {
    for (const summary of listMissions(project).filter((m) => m.mission.active)) {
      const row = getMission(project, summary.node.id);
      if (row && row.awaitingApprovalSince == null && row.status != null &&
          !['unapproved', 'abandoned', 'converged'].includes(row.status)) {
        target = { summary, row };
        break;
      }
    }
  }
  if (!target) return { ran: false, reason: 'no-actionable-mission' };
```

The rest of the function (lines 106+: `missionId`, `status`, `session`, fingerprint/debounce, invoke, `stampConductorRun`) is untouched — `target` still has the same `{ summary, row }` shape either path resolves it.

- **lazy auto-clear**: pin a mission id that doesn't correspond to any real mission (e.g. `'nonexistent-id'') while a real approved+active mission exists; call `runConductorPass`; assert it drives the real mission (`r.ran === true`, `r.missionId === forged.missionId`) AND `getConductorTargetMission(project) === null` afterward (pin was cleared).
