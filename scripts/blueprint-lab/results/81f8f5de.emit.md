## Blueprint — Assert the two-tick drive and clean pin clearing from observed per-tick evidence

### Context (what exists today)

`scripts/smoke-conductor-pin-live.ts` already drives two real ticks (`sample(1,...)` at `smoke-conductor-pin-live.ts:214-215`, `sample(2,...)` at `smoke-conductor-pin-live.ts:218-219`) and already has the raw per-tick evidence available server-side via `getConductorLastPass`/`ConductorLastPass` (`src/services/supervisor-store.ts:497-527`, exposed as `lastPass` on `GET /api/supervisor/conductor` at `src/routes/supervisor-routes.ts:905`, written every tick by `runConductorPass` at `src/services/conductor-pass.ts:92-100`, with the lazy-clear branch returning `reason: 'target-cleared'` at `src/services/conductor-pass.ts:126-131`).

But the smoke script currently:
- **Never reads `lastPass` at all.** Its Phase-3 assertions (`smoke-conductor-pin-live.ts:221-224`) infer "A moved" / "B didn't move" only from `lastConductorKey`/`updatedAt` timestamp diffs collapsed across the *whole* tick0→tick2 window (`aMoved` even folds in `mid.updatedAt` ambiguously) — it never asserts, per individual tick, that the conductor's own recorded outcome (`lastPass.reason === 'conducted'`, `lastPass.missionId === missionA`) matches what was observed at that tick.
- **Never asserts the pin-clearing evidence is clean.** Phase 4's clear-detection loop (`smoke-conductor-pin-live.ts:233-238`) only polls `targetMissionId === null` — it never checks that the *reason* the pin went null was the lazy-clear path (`lastPass.reason === 'target-cleared'`) as opposed to some other cause, and never asserts `lastPass.missionId === null` (the clean, no-mission-driven signature of that branch, since `conductor-pass.ts:130` returns `{ ran: false, reason: 'target-cleared' }` with no `missionId`, and `conductor-pass.ts:95` maps `missionId: result.missionId ?? null`).

This leaf closes that gap: pull `lastPass` alongside every existing sample, thread it through `Sample`/`transcript`, and add `check(...)` assertions (matching the file's existing `check()` convention, `smoke-conductor-pin-live.ts:55-58`) that assert against it directly — this is "asserting from observed per-tick evidence" instead of inferring from timestamp diffs.

### Exact change shape

All changes are in **`scripts/smoke-conductor-pin-live.ts`**. No other file changes; no new files.

**1. Extend the `Sample` interface** (`smoke-conductor-pin-live.ts:92-99`) to carry the per-tick conductor-pass evidence:
```ts
interface Sample {
  tick: number;
  missionId: string;
  lastConductorKey: string | null;
  lastNudgeAt: number | null;
  updatedAt: number;
  conductorTarget?: string | null;
  conductorPassReason: string | null;
  conductorPassMissionId: string | null;
}
```

**2. Change `sample()`'s signature** (`smoke-conductor-pin-live.ts:109-120`) to accept the already-fetched `lastPass` object (per-project, so callers fetch it once per tick and pass it to both missions' `sample()` calls, not re-fetch per mission):
```ts
async function sample(
  tick: number, project: string, missionId: string,
  conductorTarget?: string | null,
  lastPass?: { missionId: string | null; reason: string } | null,
): Promise<Sample> {
  const m = await missionRow(project, missionId);
  const s: Sample = {
    tick, missionId,
    lastConductorKey: m.lastConductorKey,
    lastNudgeAt: m.lastNudgeAt,
    updatedAt: m.updatedAt,
    conductorTarget,
    conductorPassReason: lastPass?.reason ?? null,
    conductorPassMissionId: lastPass?.missionId ?? null,
  };
  transcript.push(s);
  return s;
}
```

**3. In Phase 3** (`smoke-conductor-pin-live.ts:203-224`), fetch `GET /api/supervisor/conductor` once before each of the tick-1 and tick-2 sample pairs, and pass its `.body.lastPass` into both `sample()` calls at that tick:
```ts
const before = await sample(0, scratchProject, missionA, pinGet.body.targetMissionId, pinGet.body.lastPass);
await sample(0, scratchProject, missionB, pinGet.body.targetMissionId, pinGet.body.lastPass);

if (!liveMode) { startOrchestrator!(); started = true; }

await sleep(CONDUCTOR_INTERVAL_MS + 5_000);

const mid = await sample(1, scratchProject, missionA, undefined, tick1Conductor.body.lastPass);
await sample(1, scratchProject, missionB, undefined, tick1Conductor.body.lastPass);

await sleep(CONDUCTOR_INTERVAL_MS + 5_000);
const tick2Conductor = await get(`/api/supervisor/conductor?project=${encodeURIComponent(scratchProject)}`);
const after = await sample(2, scratchProject, missionA, undefined, tick2Conductor.body.lastPass);

```

**4. Add explicit per-tick evidence assertions**, immediately after the existing `aMoved`/`bMoved` checks (after `smoke-conductor-pin-live.ts:224`), reading straight off `transcript` by `tick`/`missionId` rather than ad hoc locals:
```ts
const tick1Evidence = transcript.find((s) => s.tick === 1 && s.missionId === missionA)!;
const tick2Evidence = transcript.find((s) => s.tick === 2 && s.missionId === missionA)!;
check(
  'tick 1 conductor pass reports it drove mission A (conducted, observed via lastPass)',
  tick1Evidence.conductorPassReason === 'conducted' && tick1Evidence.conductorPassMissionId === missionA,
  `lastPass=${JSON.stringify({ reason: tick1Evidence.conductorPassReason, missionId: tick1Evidence.conductorPassMissionId })}`,
);
check(
  'tick 2 conductor pass reports it drove mission A (conducted, observed via lastPass)',
  tick2Evidence.conductorPassReason === 'conducted' && tick2Evidence.conductorPassMissionId === missionA,
  `lastPass=${JSON.stringify({ reason: tick2Evidence.conductorPassReason, missionId: tick2Evidence.conductorPassMissionId })}`,
);
const bNeverDriven = transcript.filter((s) => s.tick >= 1).every((s) => s.conductorPassMissionId !== missionB);
check('mission B is never reported as the driven mission across the two-tick window', bNeverDriven);
```

**5. In Phase 4's clear-detection loop** (`smoke-conductor-pin-live.ts:233-239`), capture and assert on `lastPass` from the same poll response instead of only `targetMissionId`:
```ts
let cleared = false;
let clearEvidence: { missionId: string | null; reason: string } | null = null;
for (let i = 0; i < 3 && !cleared; i++) {
  await sleep(CONDUCTOR_INTERVAL_MS + 5_000);
  const g = await get(`/api/supervisor/conductor?project=${encodeURIComponent(scratchProject)}`);
  if (g.body.targetMissionId === null) { cleared = true; clearEvidence = g.body.lastPass; }
}
check('conductor target lazily cleared (target-cleared, conductor-pass.ts:130)', cleared);
check(
  'clean clear: lastPass reason is target-cleared with no mission driven',
  clearEvidence?.reason === 'target-cleared' && clearEvidence?.missionId === null,
  `lastPass=${JSON.stringify(clearEvidence)}`,
);
```

No changes to Phase 0/1/2/5, `markCriterionMet`, cleanup, or the final transcript dump/exit code logic.

- Phase 3 contains a `check('tick 1 conductor pass reports it drove mission A ...', ...)` call and a `check('tick 2 conductor pass reports it drove mission A ...', ...)` call, each testing `conductorPassReason === 'conducted' && conductorPassMissionId === missionA`.
- Phase 3 contains a `check('mission B is never reported as the driven mission across the two-tick window', ...)` call testing `transcript` entries with `tick >= 1`.
- Phase 4's clear-detection block contains a `check('clean clear: lastPass reason is target-cleared with no mission driven', ...)` call testing `reason === 'target-cleared' && missionId === null`.
