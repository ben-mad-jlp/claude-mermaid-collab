## Blueprint

**Goal:** Add test coverage proving `DaemonNodesMatrix` renders the three orchestration-pipeline rows (`forge`, `conductor`, `planner`) inside the `orchestration` group, and that editing them (model/effort/provider) POSTs correctly — mirroring the existing coverage pattern for `blueprint`/`implement`/`review`/`report`.

### Context established by reading the code

- `ui/src/components/settings/DaemonNodesMatrix.tsx` already fully supports this: `renderRow` (line 140) emits `data-testid="node-row-${kind}"`, `node-provider-${kind}` (or `node-provider-${kind}-locked` when `r.mcpForced`), `node-model-${kind}`, `node-effort-${kind}` (or `node-effort-${kind}-na` for grok rows). The grouped-render branch (line 239) wraps each group's rows in `<tbody data-testid="node-group-${g.key}">` with a `<tr data-testid="node-group-header-${g.key}">`. No production code changes are needed — this is pure test coverage of already-shipped behavior.
- `src/services/node-kinds.ts` defines `OrchestrationNodeKind = 'forge' | 'conductor' | 'planner'` and `ORCHESTRATION_NODE_PROFILE`:
  - `forge`: `allowedTools: 'Read Grep Glob Bash'` → **no** `mcp__` → `mcpForced: false` (real provider selector).
  - `conductor`: allowedTools includes many `mcp__mermaid__*` tools → `mcpForced: true` (locked provider).
  - `planner`: allowedTools includes `mcp__mermaid__get_task_graph` etc. → `mcpForced: true` (locked provider).
  - All three default `model: 'opus'`, `effort: 'high'`.
- `src/routes/orchestrator-routes.ts` `kindRequiresMcp` (line 67) computes `mcpForced` server-side from `allowedTools.includes('mcp__')`, confirming the above, and `LEAF_NODE_GROUPS`'s `orchestration` entry (leaf-executor.ts:711-717) has `kinds: ORCHESTRATION_NODE_KINDS` (`['forge','conductor','planner']`), `defaultCollapsed: false`.
- `ui/src/components/settings/DaemonNodesMatrix.test.tsx` currently has zero coverage of the `orchestration` group or these three kinds — existing `groups` fixtures (`GROUPS_GET_BODY`, line 87) only cover `floor`/`waves`/`verify-cad`/`zen`.

### Exact change

In `ui/src/components/settings/DaemonNodesMatrix.test.tsx`, add one new top-level `describe('DaemonNodesMatrix — orchestration rows (forge/conductor/planner)', ...)` block (after the existing `'DaemonNodesMatrix — grouped by pipeline'` block, before the broadcast-dialog block), containing:

1. An `ORCH_GET_BODY` fixture object: same shape as `GROUPS_GET_BODY`, with a single `groups: [{ key: 'orchestration', label: 'Orchestration', firesWhen: '...', kinds: ['forge','conductor','planner'], defaultCollapsed: false }]` and `rows: [forge, conductor, planner]`, where `forge.mcpForced = false`, `conductor.mcpForced = true`, `planner.mcpForced = true`, all with `defaultModel: 'opus'`, `defaultEffort: 'high'`, `effectiveProvider: 'claude'`.

2. `it('renders forge, conductor, and planner rows under the orchestration group', ...)`: mocks `global.fetch` to resolve `ORCH_GET_BODY`, renders `<DaemonNodesMatrix project="/abs/p" />`, waits for `screen.getByTestId('node-group-header-orchestration')`, then within `screen.getByTestId('node-group-orchestration')` asserts `node-row-forge`, `node-row-conductor`, `node-row-planner` are all present; asserts `node-provider-forge` (real selector) exists while `node-provider-conductor-locked` / `node-provider-planner-locked` exist and `node-provider-conductor` / `node-provider-planner` are absent (`queryByTestId` → null).

3. `it('editing the conductor row model POSTs kind=conductor to node-profiles', ...)`: mocks `fetch` recording calls, renders, waits for `node-model-conductor`, `fireEvent.change(..., { target: { value: 'sonnet' } })`, asserts a captured POST call has `body.kind === 'conductor' && body.model === 'sonnet'`.

4. `it('editing the forge row effort POSTs kind=forge to node-profiles', ...)`: same pattern on `node-effort-forge` changing to `'max'`, asserting `body.kind === 'forge' && body.effort === 'max'`.

These four tests mirror the existing `'DaemonNodesMatrix — provider column'` and `'— effort gating'` blocks' structure/assertions exactly, just parameterized on the orchestration kinds.
