### Change shape

**1. New pure predicate function**, placed directly above `classifyCriterion` (after `namesVerificationCommand`, ~line 236):

```ts
// Artifact filename extensions that are RUNTIME OUTPUTS, never source: a criterion
// citing one of these is citable against the produced file, not the diff.
const ARTIFACT_EXTENSION_RE = /\b[\w./-]+\.(md|json|csv|log|txt|yaml|yml|html|xml)\b/i;

// Source-code extensions: a filename ending in one of these is a code citation, not
// a produced artifact, even if it also happens to match ARTIFACT_EXTENSION_RE's shape
// (defense-in-depth; ARTIFACT_EXTENSION_RE's enumeration already excludes these).
const SOURCE_EXTENSION_RE = /\.(ts|tsx|js|jsx|mjs|cjs|py|go|rs|java|c|cc|cpp|h|hpp|rb|swift|kt|scala|php|cs)\b/i;

// Positive, readable-property verbs: the criterion must assert something the artifact
// CONTAINS/RECORDS, never merely that a command touching it succeeded.
const ARTIFACT_POSITIVE_VERB_RE = /\b(contains?|records?|includes?|shows?|reports?|lists?|has)\b/i;

// Absence/negation guards: if present, this is NOT a positive assertion — defer to
// Rule 3 (convictOnAbsence) instead of acquitting here.
const ARTIFACT_NEGATION_RE = /\b(no|not|without|unchanged|untouched|nothing)\b/i;

/** Rule 0.5 — ACQUIT on output-artifact content assertion: a criterion naming a concrete
 *  output-artifact file (.md/.json/.csv/… — source extensions excluded) and asserting a
 *  POSITIVE, readable property of it (contains/records/includes/…) is citable against the
 *  artifact the review will read, even though the artifact is a runtime output and never
 *  appears in the declared change-set. Requires a concrete filename (never acquits a
 *  suite-wide "tests pass") and is positive-only (never masks an absence like
 *  "config.json unchanged" — those fall through to Rule 3 unchanged). */
function acquitOnArtifactContentAssertion(text: string): boolean {
  const match = text.match(ARTIFACT_EXTENSION_RE);
  if (!match) return false;
  if (SOURCE_EXTENSION_RE.test(match[0])) return false;
  if (ARTIFACT_NEGATION_RE.test(text)) return false;
  return ARTIFACT_POSITIVE_VERB_RE.test(text);
}
```

### Why this satisfies the spike shapes and rejects the traps
- `"results/report.md contains a ## GATE verdict section"` → matches `.md`, positive verb `contains`, no negation → acquitted, `kind: 'command-result'`.
- `"after running the harness, score.json records the match rate"` → matches `.json`, positive verb `records`, no negation → acquitted.
- `"tests pass"` → no artifact-extension filename present → rule doesn't fire → falls through unchanged to existing `convictOnCommandResult` (still uncitable, unchanged behavior).
- `"config.json unchanged"` → matches `.json`, but `ARTIFACT_NEGATION_RE` catches `unchanged` → rule doesn't fire → falls through to existing `convictOnAbsence`, still convicted as `absence`.
- `"leaf-executor.ts contains a new function"` → `ARTIFACT_EXTENSION_RE`'s enumeration doesn't include `.ts` at all, so no match → rule doesn't fire (the `SOURCE_EXTENSION_RE` check is a documented defense-in-depth belt-and-suspenders, not load-bearing here).
