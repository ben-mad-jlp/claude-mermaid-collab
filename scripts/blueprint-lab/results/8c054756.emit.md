## Blueprint: Orchestrator + report + GATE verdict

### Context

`scripts/blueprint-lab/` currently has `corpus.ts`, `emit.ts`, and `score.ts` — a three-stage measurement pipeline for the blueprint node's v2 DiffContract emission (mined from real landed leaves). What's missing is the top-level orchestrator that chains `emit.ts → score.ts`, renders a human-readable report, and computes a mechanical PASS/ESCALATE gate verdict from the aggregate stats.

- `emit.ts` (`scripts/blueprint-lab/emit.ts`) writes `results/run.json` shaped as `{ total, parsed, unparsed, results: EmitResult[] }` where `EmitResult = { id, leafKindExpected, contract: DiffContract | null, rawText }`.
- `score.ts` (`scripts/blueprint-lab/score.ts`) reads `results/run.json` and writes `results/score.json` shaped as `{ scores: CaseScore[], aggregate: AggregateStats }`. `AggregateStats = { total, validationCounts: Record<string, number>, meanMatchRate, totalMatched, totalUndeclaredActual, totalDeclaredButUntouched, leafKindMismatchCount }`. `validationCounts` keys are `'accept' | 'parse-null' | 'missing:<DiffRequirementKind>'`.
- `src/services/diff-contract.ts:99` `validateContractForKind(contract, kind)` returns `{ underspecified: true, missingField }` or `{ underspecified: false }` — this is what `score.ts` already calls; the orchestrator does not call it directly.
- Both `emit.ts` and `score.ts` are sealed per their own file-header comments: the orchestrator must shell out to them as child processes (e.g. via `bun run <path>`) and only read back their persisted `results/run.json` / `results/score.json`, never import their internals.

### Change shape

Create `scripts/blueprint-lab/run.ts`:
- Resolve repo root via `execFileSync('git', ['rev-parse', '--show-toplevel'])`.
- `runChildOrThrow(scriptRelPath, args)`: `spawnSync('bun', ['run', scriptRelPath, ...args], { cwd: REPO_ROOT, stdio: 'inherit' })`; throw if `res.status !== 0`.
- `main()`: forward `process.argv.slice(2)` (optional case-id filters) to `emit.ts`, then run `score.ts` with no args. Read back `results/run.json` and `results/score.json` from `join(import.meta.dir, 'results')`.
- `computeGateVerdict(agg: AggregateStats)`: compute `acceptRate = validationCounts['accept'] / total` (0 when total is 0). Two thresholds, `GATE_MIN_ACCEPT_RATE = 0.7` and `GATE_MIN_MATCH_RATE = 0.6`:
  - `acceptRate >= 0.7 && meanMatchRate >= 0.6` → `{ verdict: 'PASS', reason }`.
  - `acceptRate < 0.7` → `{ verdict: 'ESCALATE', reason, recommendation }`, picking the recommendation by the dominant non-accept rejection bucket (`parse-null` → "add a prose+normalize fallback pass"; `missing:<field>` → "add a bounded repair-loop retry naming the missing requirement kind").
  - otherwise (accept rate OK, match rate low) → `{ verdict: 'ESCALATE', reason, recommendation: 'redesign — syntactically valid but factually wrong contracts' }`.
- `buildReport(run, score, gate)`: build a markdown string with sections `# blueprint-lab report` (totals, parsed/unparsed, model/effort from `BLUEPRINT_MODEL`/`BLUEPRINT_EFFORT` env), `## Acceptance table` (one row per `score.scores` entry: id, title from `CORPUS` lookup, expected/actual leafKind, validation, match rate), `## Rejection-mode breakdown` (table over `aggregate.validationCounts`), `## Match-rate summary` (mean/matched/undeclared/declared-but-untouched/leafKind-mismatch counts), `## GATE verdict` (verdict + reason + optional recommendation).
- Write the report to `results/report.md`; log the gate verdict to stdout; set `process.exitCode = gate.verdict === 'PASS' ? 0 : 1`.
- Import `CORPUS, type CorpusCase` from `./corpus` for title lookups only (read-only, matches the sealed-script constraint since `corpus.ts` isn't sealed).

Create `scripts/blueprint-lab/README.md`: usage (`bun run scripts/blueprint-lab/run.ts [caseId...]`, standalone per-stage commands), env vars (`BLUEPRINT_MODEL`, `BLUEPRINT_EFFORT`), output files list (`results/run.json`, `results/score.json`, `results/report.md`, `results/<id>.emit.md`), and a scope note that this is a standalone lab harness that never wires into `leaf-executor.ts` / the daemon pipeline / `diff-contract.ts` and never mutates live todo/mission state.

### Acceptance criteria
- `scripts/blueprint-lab/run.ts` exports/defines `computeGateVerdict` that returns a `GateVerdict` with `verdict: 'PASS' | 'ESCALATE'`.
- `scripts/blueprint-lab/run.ts`'s `main()` calls `runChildOrThrow('scripts/blueprint-lab/emit.ts', ...)` followed by `runChildOrThrow('scripts/blueprint-lab/score.ts', [])`, then reads `results/run.json` and `results/score.json`.
- `scripts/blueprint-lab/run.ts` writes `results/report.md` via `buildReport(...)` containing a `## GATE verdict` section.
- `scripts/blueprint-lab/README.md` documents the `bun run scripts/blueprint-lab/run.ts` entrypoint and the `BLUEPRINT_MODEL`/`BLUEPRINT_EFFORT` env vars.
