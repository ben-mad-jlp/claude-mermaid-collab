## Blueprint: Live end-to-end sweep-measurement harness script

### Context (grounded in repo state)

`src/services/sweep-measurement.ts` exports `runSweepMeasurement(project, opts?)` (line 55), a composed primitive that force-runs 5 steps in dependency order and returns a `SweepMeasurement` snapshot (lines 33-41). It is **completely untested and unwired today** — no test file, no route, no caller anywhere (`grep -rn "sweep-measurement"` hits only its own file). Its doc comment (lines 4-6) states its entire purpose: "a caller can diff across two consecutive runs to test idempotence" — that claim has never been exercised against real git/store state, only injected fakes exist elsewhere in the codebase (e.g. `src/services/__tests__/landed-epic-sweep.test.ts` uses a fake `GitProbe`).

The primitive is fully hermetic via injectable `probe`/`runner` (`RunSweepMeasurementOpts`, lines 43-47), defaulting to `makeGitProbe(project)` (`src/services/epic-branch-status.ts:180`, runs real `git rev-list`/`merge-tree` subprocess calls rooted at the `project` path) and `makeBranchGcRunner(project)` (`src/services/landed-epic-sweep.ts:112`, runs real `git branch -D`). "Live end-to-end" means calling `runSweepMeasurement(project)` with **no `probe`/`runner` overrides**, against a real scratch git repo and real store rows — the one path that currently has zero coverage.

Repo convention for this exact shape is `scripts/worker-core-smoke.ts` (mkdtemp scratch dir + real `git init` + direct in-process function call, no HTTP) crossed with `src/services/__tests__/landed-epic-sweep.test.ts`'s real-store seeding (`createTodo`, `upsertMission`, `addCriterion`, `setCriterionMet`, `completeTodo`, `stampEpicLandedAt`, `MERMAID_SUPERVISOR_DIR` env var) and `scripts/smoke-conductor-pin-live.ts`'s `check(name, ok, detail)` ✅/❌ accumulator + nonzero exit on failure. Scripts are plain `.ts` run via `bun run scripts/<name>.ts`; npm-script aliases follow `<category>:<kebab-slug>` (e.g. `package.json:29` `"live:conductor-pin-evidence": "bun run scripts/live-conductor-pin-evidence.ts"`).

### Change shape

**New file: `scripts/live-sweep-measurement-harness.ts`**

1. Header comment stating it drives `runSweepMeasurement` against a real scratch repo, zero blast radius (mirrors `scripts/worker-core-smoke.ts:1-8` style).
2. `const project = mkdtempSync(join(tmpdir(), 'sweep-measurement-live-'))`; `execSync('git init -q && git config user.email ... && git config user.name ... && git commit -q --allow-empty -m init', { cwd: project })`; set `process.env.MERMAID_SUPERVISOR_DIR = project`.
3. Guard with `isSelfProject` (`src/services/deploy-service.ts:106`) — abort if it ever somehow resolves true (defense-in-depth, matches `scripts/smoke-conductor-pin-live.ts`'s pattern).
4. Seed real state via the actual store APIs (no mocks):
   - A converged mission: `createTodo` (mission kind) → `upsertMission` → `addCriterion` → `setCriterionMet(..., true)` (mirrors `landed-epic-sweep.test.ts:32-36 seedConvergedEpic`).
   - Epic A ("merge me"): `createTodo` (epic kind) → `completeTodo(..., 'accepted')` → `stampEpicLandedAt`; create its real branch via `execSync('git branch ' + epicBranchName(epicA.id))` at current HEAD (so `ahead===0` for real).
   - Epic B ("diverge me"): same real-branch creation, but make one extra real commit on that branch only (`git checkout -b <branch>`, commit, `git checkout master`) so `ahead>0` for real.
   - A second mission/session with `upsertMission` + `queuePos` set, no active mission for that `ownerSession`, to exercise `sessionsZeroActiveWithQueuedApproved`.
5. `const first = runSweepMeasurement(project)` — **no `probe`/`runner` opts**, exercising `makeGitProbe`/`makeBranchGcRunner` for real.
6. `check()` assertions on `first`: `gcDeleted` contains `epicBranchName(epicA.id)`; `gcFlagged` contains `epicB.id`; `sessionsZeroActiveWithQueuedApproved` contains the seeded session.
7. `const second = runSweepMeasurement(project)` (same, no opts) — assert `second.gcDeleted` is empty (branch already gone) and `second.gcFlagged` still contains `epicB.id`, proving the documented idempotence claim for real, not just in theory.
8. Print a summary count of passed/failed checks; `finally` block: `delete process.env.MERMAID_SUPERVISOR_DIR`; `rmSync(project, { recursive: true, force: true })`; `process.exit(anyFailed ? 1 : 0)`.

**Edit `package.json`**: add `"live:sweep-measurement": "bun run scripts/live-sweep-measurement-harness.ts",` next to the existing `"live:conductor-pin-evidence"` entry (line 29), following the established `<category>:<kebab-slug>` naming.
